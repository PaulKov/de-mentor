# XML, XPath и XSLT

## Структура XML
- Узел имеет имя и пространство имён
- Атрибуты и дочерние элементы читаются по-разному
- Повторяющиеся элементы образуют последовательность
```xml
<Order xmlns="urn:lab:orders">
  <Id>o-101</Id>
  <Customer id="c-1"/>
</Order>
```
> Взгляните на заказ в XML. Корневой элемент называется Order.
> Идентификатор заказа находится в дочернем элементе, а у клиента он в атрибуте.
> Объявление xmlns задаёт пространство имён для элементов без префикса.
> Полное имя элемента образуют адрес пространства имён и локальное имя.
> Почему это важно, если на экране два совершенно одинаковых слова Order?
> Они могут принадлежать разным словарям и означать разные типы документа.
> Для выбора узла нам понадобятся обе части имени.

## XPath и default namespace
- Префикс o связывается с urn:lab:orders
- Абсолютный путь начинается с корня
- Customer/@id обращается к атрибуту
```xpath
/o:Order/o:Id
/o:Order/o:Customer/@id
count(/o:Order/o:Lines/o:Line)
```
> В XPath первой версии имя элемента без префикса ищется без пространства имён.
> Поэтому простой путь из имён на слайде может дать пустой результат.
> В таблице стилей свяжите префикс с адресом пространства имён заказа.
> Используйте этот префикс на каждом шаге пути к элементу.
> В исходном файле префикс может быть другим. Сравнивается полный адрес.
> Атрибут id записан без префикса и не наследует пространство имён элемента.
> Сравните значение поля заказа, атрибут клиента и число позиций.

## Чтение XSLT
- template match выбирает контекст входа
- for-each проходит по позициям
- Attribute value template вычисляет значение
```xml
<xsl:template match="/o:Order">
  <normalized-order id="{o:Id}">
    <!-- Вложенные шаблоны и элементы -->
  </normalized-order>
</xsl:template>
```
> XPath выбирает узлы, а XSLT строит из них выходной документ.
> Условие match выбирает заказ, к которому применяется шаблон.
> Выражение в фигурных скобках подставляет идентификатор в выходной атрибут.
> Цикл for-each поочерёдно делает каждую позицию текущим узлом.
> Поэтому код товара и количество читаются из атрибутов именно этой позиции.
> Если шаблон не подошёл, встроенные правила могут вывести один текст.
> Проверьте имя корня и число позиций, даже если процессор сообщил об успехе.

## SOAP и входные ограничения
- SOAP Envelope содержит Body, иногда Fault
- Transport status и бизнес-ошибка проверяются отдельно
- Внешние XML ресурсы и большие документы требуют ограничений
> В SOAP полезный документ находится внутри тела конверта.
> При ошибке в теле может появиться элемент Fault с описанием причины.
> Учебный сервис умеет вернуть этот элемент и со статусом 200, и со статусом 500.
> Сравните оба ответа. Какую ветку потока должен выбрать каждый из них?
> Согласуйте с источником допустимые размер, глубину и схему документов.
> Ограничьте доступ парсера к внешним ресурсам и проверьте настройки своей версии.
> В карантине оставьте координаты запроса, чтобы ответ можно было найти позднее.
